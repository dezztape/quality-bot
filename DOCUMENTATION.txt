1. ОБЩЕЕ ОПИСАНИЕ
================================================================================

Quality Bot - это интеллектуальная система для проведения и управления тестами
контроля качества через Telegram. Бот позволяет администраторам создавать и
распространять тесты, а сотрудникам - проходить их с автоматической проверкой
и отслеживанием прогресса.

Ключевые преимущества:
  ✓ Полностью автоматизированная система тестирования
  ✓ Двух-типовая система тестов (Контроль и Опыт)
  ✓ Система одобрения администратором перед публикацией
  ✓ Автоматическая повторная попытка при ошибке
  ✓ Детальная аналитика и экспорт результатов
  ✓ Простой интерфейс в популярном мессенджере (Telegram)

2. ТЕХНОЛОГИЧЕСКИЙ СТЕК
================================================================================

Основные технологии:
  • Framework: aiogram 3.20.0 (асинхронный Telegram API wrapper)
  • Язык: Python 3.12
  • База данных: PostgreSQL 12+
  • ORM: SQLAlchemy 2.0.40
  • Драйвер БД: asyncpg 0.30.0
  • Экспорт: openpyxl 3.1.5 (для Excel)
  • Хранилище состояний: MemoryStorage (FSM)

Архитектура:
  • Полностью асинхронная обработка событий
  • Параллельная работа с несколькими пользователями
  • Оптимизированные SQL запросы
  • Безопасная работа с БД через транзакции

4. СТРУКТУРА БАЗЫ ДАННЫХ
================================================================================

4.1 ТАБЛИЦА USERS (Пользователи)
────────────────────────────────────────────────────────────────────────────
  id (int, primary key)
  telegram_id (bigint, unique) - Уникальный ID в Telegram
  full_name (string) - ФИО сотрудника
  city (string) - Город (для аналитики)
  is_whitelisted (boolean) - Разрешение на участие в тестах

4.2 ТАБЛИЦА TESTS (Тесты)
────────────────────────────────────────────────────────────────────────────
  id (int, primary key)
  title (string) - Название теста (например, "Тест 2026-05-19")
  test_date (date) - Дата проведения теста
  active (boolean) - Активен ли тест
  approved (boolean) - Одобрен ли тест администратором

4.3 ТАБЛИЦА QUESTIONS (Вопросы)
────────────────────────────────────────────────────────────────────────────
  id (int, primary key)
  test_id (int, foreign key) - Ссылка на тест
  test_type (string) - Тип: "control" (контроль) или "experience" (опыт)
  question_order (int) - Номер вопроса (отдельный счетчик на тип)
  image_file_id (string) - ID изображения в Telegram
  correct_answer (int 1-10) - Правильный ответ

4.4 ТАБЛИЦА ANSWERS (Ответы пользователей)
────────────────────────────────────────────────────────────────────────────
  id (int, primary key)
  user_id (int, foreign key) - Ссылка на пользователя
  question_id (int, foreign key) - Ссылка на вопрос
  answer (int 1-10) - Ответ пользователя

4.5 ТАБЛИЦА TEST_SESSIONS (Сессии прохождения тестов)
────────────────────────────────────────────────────────────────────────────
  id (int, primary key)
  user_id (int, foreign key) - Ссылка на пользователя
  test_id (int, foreign key) - Ссылка на тест
  test_type (string) - Тип теста ("control" или "experience")
  current_question (int) - Текущий номер вопроса
  completed (boolean) - Завершена ли сессия
  attempts (int) - Количество попыток для прохождения

5. ПРОЦЕСС РАБОТЫ БОТА
================================================================================

5.1 ПОЛНЫЙ ЦИКЛ РАБОТЫ СИСТЕМЫ
────────────────────────────────────────────────────────────────────────────

ШАГ 1: ПОДГОТОВКА
  └─ Администратор нажимает "➕ Добавить вопрос"
  └─ Выбирает тип теста (Контроль или Опыт)
  └─ Загружает изображение вопроса
  └─ Указывает правильный ответ (1-10)
  └─ Вопрос сохраняется в БД с автоматическим номером
  └─ Повторяет процесс для всех вопросов обоих типов

ШАГ 2: ОДОБРЕНИЕ
  └─ После добавления всех вопросов админ нажимает "📢 Уведомление"
  └─ Система устанавливает флаг approved = True для теста
  └─ Система отправляет уведомление всем сотрудникам

ШАГ 3: ПРОХОЖДЕНИЕ ТЕСТОВ СОТРУДНИКАМИ
  └─ Сотрудник получает уведомление о готовности теста
  └─ Нажимает "📝 Пройти тест"
  └─ Выбирает тип теста (Контроль или Опыт)
  └─ Получает первый вопрос (изображение + 10 кнопок ответов)
  └─ Отвечает на все вопросы выбранного типа
  └─ Может потом выбрать другой тип и пройти его

ШАГ 4: ПРОВЕРКА ОТВЕТОВ
  └─ После последнего вопроса система загружает все ответы
  └─ Сравнивает каждый ответ с correct_answer
  └─ Если все правильно → "✅ Тест завершен"
  └─ Если есть ошибка → "❌ Тест не пройден, попытка #2"
     └─ Удаляются все ответы
     └─ Счетчик попыток +1
     └─ Тест начинается заново

ШАГ 5: ПРОСМОТР РЕЗУЛЬТАТОВ
  └─ Администратор нажимает "📊 Статистика"
  └─ Выбирает тип теста
  └─ Видит полный список сотрудников с результатами:
     └─ Имя и город
     └─ Процент правильных ответов
     └─ Количество попыток
     └─ Статус (Завершен/В процессе/Не начат)

ШАГ 6: ЭКСПОРТ ДАННЫХ
  └─ Администратор нажимает "📁 Экспорт CSV"
  └─ Система создает Excel файл со всеми данными
  └─ Отдельный лист для каждого сотрудника
  └─ Автоматический расчет итогов

5.2 СИСТЕМА РАЗДЕЛЕНИЯ ПО ТИПАМ ТЕСТОВ
────────────────────────────────────────────────────────────────────────────

Один тест может содержать два типа вопросов:

КОНТРОЛЬ (control)
  • Вопросы нумеруются: 1, 2, 3, ...
  • Сотрудник отвечает на вопросы контроля
  • Тест считается завершенным, когда все ответы правильны

ОПЫТ (experience)
  • Вопросы нумеруются отдельно: 1, 2, 3, ...
  • Сотрудник может пройти после контроля
  • Или вместо контроля, если выберет
  • Каждый тип отслеживается отдельно

Преимущества:
  ✓ Независимые попытки для каждого типа
  ✓ Не влияют друг на друга
  ✓ Удобно сравнивать результаты контроля и опыта
  ✓ Возможность проходить их в любом порядке

5.3 МЕХАНИЗМ ПРОГРЕССА ПОЛЬЗОВАТЕЛЯ
────────────────────────────────────────────────────────────────────────────

В памяти бота хранится структура:
  user_progress = {
    user_id: {
      "control": текущий_номер_вопроса,
      "experience": текущий_номер_вопроса
    }
  }

Это позволяет:
  • Отслеживать текущий вопрос для каждого типа
  • Не путать прогресс между типами
  • Быстро загружать правильный вопрос
  • Сохранять прогресс до завершения теста

ПРОБЛЕМА 1: Кнопка "Просмотреть тест" не работала

  РЕШЕНИЕ: Переместили универсальный обработчик в конец файла

ПРОБЛЕМА 2: Не удавалось пройти оба типа тестов в один день
  ПРИЧИНА: user_progress хранил только один индекс для всех типов
  РЕШЕНИЕ: Изменили на структуру Dict[int, Dict[str, int]]
  РЕЗУЛЬТАТ: Каждый тип отслеживается независимо

ПРОБЛЕМА 3: Excel экспорт был пустой
  ПРИЧИНА: Использовался неправильный ID при выборке пользователя
  РЕШЕНИЕ: Исправлена логика выборки User по user_id вместо telegram_id
  РЕЗУЛЬТАТ: Экспорт работает корректно

ПРОБЛЕМА 4: Вопросы нумеровались неправильно
  ПРИЧИНА: Не фильтровались по test_type при подсчете
  РЕШЕНИЕ: Добавлена фильтрация по test_type в SQL запрос
  РЕЗУЛЬТАТ: Нумерация идет отдельно для каждого типа

ПРОБЛЕМА 5: Тест блокировался при переходе между типами
  ПРИЧИНА: get_active_test() требовала approved=True на каждом шаге
  РЕШЕНИЕ: Создана отдельная get_test_for_passing() без проверки одобрения
  РЕЗУЛЬТАТ: Сотрудники могут переходить между типами без блокировки

7. ПРОИЗВОДИТЕЛЬНОСТЬ И МАСШТАБИРУЕМОСТЬ
================================================================================

7.1 ТЕКУЩИЕ ХАРАКТЕРИСТИКИ
────────────────────────────────────────────────────────────────────────────

Пиковая нагрузка:
  • 20+ сотрудников одновременно → возможно, но медленно
  • 10-15 сотрудников одновременно → комфортно
  • 100+ операций в минуту → обрабатывается нормально

Проблемные места:
  1. Connection Pool PostgreSQL (по умолчанию ~10 соединений)
  2. MemoryStorage для состояний (потеряются при перезагрузке)
  3. Один экземпляр бота на одном сервере

7.2 РЕКОМЕНДАЦИИ ДЛЯ МАСШТАБИРОВАНИЯ
────────────────────────────────────────────────────────────────────────────

Для 20+ одновременных пользователей:

  1. Увеличить Connection Pool:
     pool_size=30, max_overflow=10
     Это позволит обрабатывать больше одновременных запросов

  2. Заменить MemoryStorage на Redis:
     Состояния будут сохраняться при перезагрузке
     Можно запустить несколько экземпляров бота

  3. Добавить логирование:
     Для отладки и мониторинга проблем
     Сохранение логов в файл

  4. Развернуть на отдельном сервере:
     VPS (3-10$/месяц) или облачная платформа
     Работа 24/7 без перерывов

Для 100+ пользователей в день:
  • Использовать несколько экземпляров бота с балансировщиком
  • Оптимизировать SQL запросы с индексами
  • Добавить кэширование часто используемых данных
  • Использовать асинхронный background worker для тяжелых операций

11. АДМИНИСТРИРОВАНИЕ
================================================================================

11.1 УПРАВЛЕНИЕ ПОЛЬЗОВАТЕЛЯМИ
────────────────────────────────────────────────────────────────────────────

Добавление пользователя к тестированию:
  1. Пользователь запускает /start в боте
  2. Вводит свое имя и город
  3. Администратор выполняет: /allow TELEGRAM_ID
  4. Пользователь теперь может проходить тесты

Удаление пользователя:
  Нужно удалить из базы данных через pgAdmin:
  DELETE FROM users WHERE telegram_id = TELEGRAM_ID;

11.2 УПРАВЛЕНИЕ ТЕСТАМИ
────────────────────────────────────────────────────────────────────────────

Создание теста:
  1. Администратор нажимает "➕ Добавить вопрос"
  2. Добавляет нужное количество вопросов типа "Контроль"
  3. Добавляет нужное количество вопросов типа "Опыт"
  4. Нажимает "📢 Уведомление" для публикации

Очистка и перезагрузка данных:
  
  Для полной очистки и начала заново, используйте pgAdmin:
  
  DELETE FROM answers;
  DELETE FROM test_sessions;
  DELETE FROM questions;
  DELETE FROM tests;
  
  После этого можно добавлять новые вопросы и проводить тест заново.

13. ПОДДЕРЖКА И РЕШЕНИЕ ПРОБЛЕМ
================================================================================

13.1 ЧАСТЫЕ ВОПРОСЫ
────────────────────────────────────────────────────────────────────────────

В: Пользователь может пройти тест два раза?
О: Нет, если тест уже завершен (completed=True), система не позволит пройти еще раз

В: Что произойдет, если сотрудник ошибся один раз?
О: Все его ответы будут удалены, счетчик попыток увеличится, тест начнется заново

В: Можно ли изменить ответ уже завершенного теста?
О: Нет, после завершения результаты фиксируются в БД

В: Административные пользователи видны в статистике?
О: Да, они помечаются как (Админ)

13.2 ТИПИЧНЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ
────────────────────────────────────────────────────────────────────────────

ПРОБЛЕМА: Бот не отвечает
  РЕШЕНИЕ: 
  1. Проверить, запущен ли бот (python main.py)
  2. Проверить интернет соединение
  3. Проверить, актуален ли BOT_TOKEN

ПРОБЛЕМА: Ошибка подключения к БД
  РЕШЕНИЕ:
  1. Проверить, запущен ли PostgreSQL
  2. Проверить DATABASE_URL в .env
  3. Проверить пароль базы данных
  4. Убедиться, что база создана

ПРОБЛЕМА: Экспорт не работает
  РЕШЕНИЕ:
  1. Убедиться, что тест одобрен (📢 Уведомление)
  2. Убедиться, что есть завершенные тесты
  3. Проверить права администратора

ПРОБЛЕМА: Вопросы не загружаются
  РЕШЕНИЕ:
  1. Убедиться, что вопросы добавлены
  2. Проверить, что выбран правильный тип теста
  3. Перезагрузить бота

ПРОБЛЕМА: Сотрудник не видит тест
  РЕШЕНИЕ:
  1. Выполнить /allow TELEGRAM_ID
  2. Убедиться, что тест опубликован (📢 Уведомление)
  3. Проверить, на сегодняшнюю ли дату тест
